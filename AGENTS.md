# Software changes

Apply these principles to normal software development, with depth proportional to the task.

## Think Before Coding

Inspect relevant code, project instructions, and dependencies before editing. Identify material assumptions, uncertainties, constraints, and risks; investigate when evidence is available.

## Simplicity First

Prefer the simplest correct implementation that follows project conventions. Reuse suitable code and abstractions; avoid speculative features, unnecessary dependencies, layers, and complexity.

## Surgical Changes

Change only what the approved task requires. Preserve unrelated code, user modifications, external behavior, and public contracts unless authorized otherwise. Avoid unrelated refactoring or formatting, and review the final diff for unintended changes.

## Goal-Driven Execution

Define proportionate, observable success criteria before non-trivial work. Choose verification for the change's risk; run relevant tests and checks when practical. Report actual evidence, distinguish verified results from assumptions, and stop when authorized requirements are met.
